# 审判台 HTML 规范（公开版 · 可选导出）

> **定位**：默认产物是空间（见 `空间规格.md`）。本规范只在用户明确要求单文件 HTML 时使用。
> **体积警告（实测教训）**：聊天 App 的文件预览有体积上限——约 4.7MB 的全量文件会直接提示「文件过大无法预览」，约 0.6MB 的待处理版可正常预览。出 HTML 时：①优先只出「待处理版」（只含异常），正常区一句说明带过；②若用户坚持全量版，交付时必须同时说明「App 里可能打不开，请用浏览器打开」；③交付前自己先确认文件大小并写进报告。

单文件 HTML（下称「审判台」）不拆分、不引用外部文件、不挂载数据包——打开它不需要任何其他东西。

## 设计原则（全部来自真实翻车教训）

1. **全部写死**：每条帖的卡片/行在生成时直接写进文件。禁止「打开时用脚本从内嵌数据现拼卡片」——弱预览环境（手机 App 内预览等）脚本稍慢或出错就是整页空白。
2. **该重的重、该轻的轻**：要动手的区（异常区）用全卡片；只供查阅的正常区用紧凑行。若正常区也用全卡片，万级帖子的文件会有五万多个内容块，手机上直接打不开。
3. **单文件到底**：正常区再大也放进同一个文件，用折叠＋分段加载控制打开速度，而不是拆成多个文件让人来回翻。

## 页面结构（自上而下）

0. **类别口径**：页面只认两大类——**主贴**（原始主贴＋引用＋转帖合并）与**回复**。卡片与紧凑行的类别标签只许出现「主贴 / 回复」两值；原始类型仅供内部审判使用，不出现在页面上，页头也不显示细分计数，分类计数只出现在各分组标题的计数徽标里。
1. **页头**：标题（X审判台 · @账号名）、数据源一行（官方数据包导出日期、法条基线日期）、判决分布一行（全量 T 条 · 异常 N · 正常 K，不带括号细分）、用法一句话（展开分组 → 点「打开原帖」去 X 亲手删 → 回来勾方框 → 归入已删除区；勾选存本机浏览器）。
2. **操作条**（吸顶）：已勾选计数、「看已删除区 / 看待处理」切换、导出已删 ID 按钮。
3. **异常区（下拉分组，两组）**：「异常 · 主贴」与「异常 · 回复」两个可折叠分组（details 元素），标题带红色计数徽标；主贴组默认展开。全卡片，组内按严重程度排序（违规 → 高危 → 中危 → 低危，同档按时间倒序）。
4. **同文副本不单独成区**：判合规、归正常区，在紧凑行的注记里标「同文副本，可选清理」，该行带勾选框（勾后归已删除区视图）。异常就是异常、没事就是没事，不设中间区。
5. **正常区（下拉分组，两组）**：「正常 · 主贴」与「正常 · 回复」，绿色计数徽标；组内紧凑行分段加载（每段 ≤2000 行）：每行＝日期 · 类别 · ♥数 · 正文（超长可截断至约 140 字）· 注记（如有，灰色小字）· 直达链接。
6. **页脚**：一句话——审判只给判决与建议，删除永远由账号本人完成；本页单文件离线版，数据不出设备。

## 卡片要件（异常）

- 勾选框（data-chk=帖子ID）
- 档位徽标（违规=红底、其余异常档=黑底；正常区行首绿点标识即可）
- 日期（使用者时区）· 类别（只许「主贴 / 回复」两值）
- ♥ 点赞数 · 转帖数（回复另注「回 @某某」）
- 正文全文
- 理由框：命中的法条条目＋一句话理由＋证据等级
- 处置建议一行
- 「打开原帖 ↗」链接：`https://x.com/<账号名>/status/<帖子ID>`
- 自回复链成员：以子卡形式挂在主贴卡内，各自带勾选框与链接，跟随主贴处理

## 紧凑行要件（正常区）

- 日期 · 类别 · ♥数
- 正文（一行流式排版，保留注记原文）
- 注记（如有）：验活重判、口头禅改判等说明用灰色小字跟在正文后
- 直达链接同上

## 勾选机制

- localStorage 保存已勾选帖子 ID 集合，key 用 `xjudge_<账号名>_v1`（换账号不串账）。
- 勾选后卡片变淡并归入「已删除区」视图；计数实时更新；「导出已删ID」把已勾 ID 导成 txt 备份。
- 折叠段展开后要重新纳入勾选过滤的卡片集合（脚本里统一用「异常区全部卡片＋正常区带勾选框的行」选择器收集）。

## 验收清单（交付前必做，缺一不可）

1. **条数对账**：文件内每条帖恰好出现一次；异常＋正常 ＝ 数据包帖子总数；各分区计数与页头声明一致；HTML 标签开闭平衡。
2. **真渲染亲眼看**：用浏览器或页面渲染引擎实际打开成品，手机宽度（约 420px）检查：首屏（页头＋计数＋第一张卡）、异常区中段、已删除区、正常区各看一段——不空白、不重叠、理由框与按钮都在。只查代码/语法不算验收。
3. **链接抽查**：随机抽 3 条点「打开原帖」，确认直达对应帖子。
4. **勾选实测**：勾一条 → 刷新页面 → 勾选状态还在、计数正确；切到「已删除区」能看到它。
5. 四项都过，才可以对用户说「做好了」；渲染环境不可用时必须如实说明用了什么替代验收方式。
