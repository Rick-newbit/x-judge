## 算法

### 1.1 排序公式与权重

公式：最终分 = Σ（权重 × 该动作的预测概率）。Phoenix 先对每个动作预测概率（或停留时长等连续值），RankingScorer 加权求和。权重乘的是「预测这个看帖人做该动作的概率」，不是已发生的计数。

**预测动作清单**（Phoenix 的预测头）：

- 互动：点赞、回复、转帖、引用、分享、分享（私信）、分享（复制链接）；
- 点击：点进帖子、点进主页、点开链接、点开放大图片、点开视频、点开引用帖；
- 注意力：视频优质观看、停留、停留时长、点击后停留时长、视频续看秒数、主页停留秒数；
- 作者：关注作者；
- 负向：不感兴趣、静音作者、拉黑作者、举报、划过不停留。

**权重表**（仓库内有两套参数，数值多处不同，仓库未说明线上最终以哪套为准；引用必须注明出处，两套不得混用）：

| 动作 | home-mixer | vm-ranker |
|---|---|---|
| 分享（复制链接） | 0.0 | 20.0 |
| 回复 | 5.0 | 5.0 |
| 引用转发 | 5.0 | 5.0 |
| 分享（私信转发） | 5.0 | 5.0 |
| 分享（普通分享） | 2.118 | 2.0 |
| 关注作者 | 4.0 | 4.0 |
| 转帖 | 1.0 | 1.0 |
| 点赞 | 0.708 | 0.5 |
| 点进帖子 | 0.274 | 0.3 |
| 点开链接 | 0.2 | 0.2 |
| 点开放大图片 | 0.05 | 0.05 |
| 点开引用帖 | 0.05 | 0.05 |
| 停留（动作头） | 0.05 | 0.05 |
| 未探索帖子 | 0.015 | 0.02 |
| 点开视频 | 0.0 | 0.07 |
| 主页点击 / 视频优质观看 / 引用帖优质观看 / 帖内视频播放 / Grok 分析 | 0.0 | 0.0 |
| 不感兴趣 | −53.07 | −47.52 |
| 静音作者 | −58.8 | −58.8 |
| 拉黑作者 | −31.2 | −31.2 |
| 举报 | −234.0 | −234.0 |

| 互关关系下回复的额外加成 | +15.0 | +15.0 |

**官方澄清（防误读，仓库 README 与 param.rs 注释原文口径）**：

- 不得把负权重换算成「一次举报抵消 N 个赞」：举报的基线概率比点赞低 1000 倍以上，权重大只是让罕见信号在概率尺度上可比；
- 权重预测的是每个看帖人自己采取该动作的概率：组织化拉黑/举报主要影响与操作者相似的人群，不是全网等比扣分；
- 两套参数中**没有收藏（bookmark）权重参数**，也没有 Premium 分发乘数参数，不得虚构。

### 1.2 打分后调整

RankingScorer 加权求和之后施加的调整（参数为 vm-ranker 默认值，另注出处者除外）：

| 调整 | 机制 | 参数 |
|---|---|---|
| 作者多样性衰减 | 同一作者第一帖之后，每多一帖乘以衰减因子，直至下限 | 衰减 0.5、下限 0.25 |
| 未关注折扣 | 未关注账号的帖子乘以小于 1 的因子；已关注账号的回复与转帖经 OONRescore 同样折减 | 0.75；话题类 0.5 |
| 新用户未关注因子 | 新注册用户时间线里未关注帖子的权重因子 | 0.00001 |
| 新作者扶持 | 曝光量低于阈值的作者，帖子被抬升至目标位置附近试投 | 阈值 200 次曝光、目标槽位 15–16（home-mixer） |

权重按人扰动（WeightPerturbationSigma）现行默认 0.0：默认配置下对所有人同一套权重，扰动机制不生效。

### 1.3 管线关卡

For You 请求由 Home Mixer 编排、建立在 Candidate Pipeline 框架上，共七步：

1. **Query Hydration（装载看帖人）**：近期互动序列（模型主输入）、关注列表、拉黑/静音名单、静音关键词、已看/已推帖子、关注话题；
2. **Candidate Sources（候选源并行捞帖）**：见下表；
3. **Candidate Hydration（补齐候选）**：帖子文本与媒体、作者信息与账号标签、引用帖、语言、互动计数、订阅状态；
4. **Pre-Scoring Filters（打分前过滤）**：见下；
5. **Scoring（打分）**：PhoenixScorer 给出每个动作的概率 → RankingScorer 加权求和并施加 1.2 的调整 → VMRanker 调用 vm-ranker 再排序服务，以 DPP（determinantal point process）按 embedding 重排，牺牲少量分数换相邻帖相似度降低（DppTheta 默认 0.65）；
6. **Selection（选取）**：TopKScoreSelector 按最终分取前 K 条；
7. **Post-Selection Filters（选后过滤）**：按可见性过滤裁决再剔一轮（见 1.4）。

之后 Blending Pipeline 把排序后的帖子与模型不排序的内容（广告、Who to Follow、提示、push-to-home）交织成最终时间线；响应发出后记录已推帖子等副作用。

**候选源**（现行参数默认值）：

| 候选源 | 路 | 机制 | 参数 |
|---|---|---|---|
| Thunder | 关注内 | 内存中保存所关注账号的近期帖，按看帖人关注列表返回 | 上限 1200 |
| Phoenix retrieval | 关注外 | 两塔模型：用户塔把看帖人互动历史编码为向量，候选塔以帖子的 semantic IDs（多模态 embedding 残差量化，6 层 × 256 码）＋作者 ID 哈希表示帖子，在索引上做点积近邻检索，把数百万候选收窄到千百量级 | 上限 1000；冷启动 200 |
| SimClusters | 关注外 | 按「谁与什么互动」把账号与帖子聚成兴趣簇，以簇相似度找候选，与 Phoenix retrieval 并行调用 | 启用；候选最大年龄 48 小时 |
| 热门帖列表 | 共享 | 一份共享的热门近期帖列表（初始来自最受关注的活跃账号） | 启用；衰减半衰期默认 8 小时 |
| TweetMixer | 关注外 | 旧式关注外协调层，代码保留 | 默认关闭（上限 800） |

现行版没有给出关注内/外固定比例（外界流传的百分比说法不属于现行版）；两路候选由同一个 Phoenix 模型统一打分排序。Phoenix 检索与排序用 Candidate Isolation：推理时候选之间不能互相注意，只能注意看帖人的上下文与历史——单帖分数不随同批候选变化、可缓存。2026-10 两次更新：排序对停留时长的估计改进（10-08）；检索新增「预测用户会读完帖子」的训练目标（10-13）。

**打分前过滤（Pre-Scoring Filters，共 17 项）**：

- 去重与数据：DropDuplicatesFilter（多源重复）、CoreDataHydrationFilter（元数据加载失败）、RetweetDeduplicationFilter（转帖去重）；
- 时效：AgeFilter——超过 48 小时的帖出局；
- 本人与关系：SelfTweetFilter（看帖人自己的帖）、AuthorSocialgraphFilter（被看帖人拉黑或静音的作者）、MutedKeywordFilter（静音关键词命中）；
- 关注外严规：OONRetweetReplyFilter（未关注账号的转帖/回复、父帖缺失的回复）、OONNsfwSimclustersFilter（未关注且作者被标成人内容的 SimClusters 帖）；
- 权限：IneligibleSubscriptionFilter（无权访问的订阅专属帖）；
- 已消费：PreviouslySeenPostsFilter 及 Backup 版（已看过）、PreviouslyServedPostsFilter（已推过）；
- 内容与话题：VideoFilter、TopicIdsFilter；
- 新用户：NewUserMinEngagementFilter（新账号的低互动关注外帖）；
- 实验留出：InventoryHoldoutFilter、FavHoldoutFilter。

**选后过滤（Post-Selection Filters）**：VFFilter（剔除可见性过滤裁决为 DROP 的帖）；AncillaryVFFilter（父帖、引用帖或被转帖被 DROP 的，连带剔除）；DedupConversationFilter（同一会话只保留部分分支）。

**关键代码注释（定性依据）**：一个互动动作要进入推荐系统，必须发生在 Home Timeline 被推送的帖子上；通过群聊等渠道协调、直达帖子产生的互动，对排序没有影响（param.rs 注释原文口径）。互关 +15.0 加成同理，只认时间线内自然发生的回复。

### 1.4 可见性过滤与账号标签

**可见性过滤（Visibility Filtering）** 在排序后做最终裁决，四种结果：

| 裁决 | 含义 |
|---|---|
| ALLOW | 正常展示 |
| NOTICE | 附提示展示 |
| INTERSTITIAL | 置于可点击穿透的提示页之后（如成人/血腥媒体） |
| DROP | 不展示 |

裁决输入 = 标注管线产出的帖子/账号标签 ＋ 看帖人与作者的关系（拉黑、静音、关注、作者账号 protected / suspended / deactivated、订阅状态）＋ 看帖人设置与所在国家。规则按注册表顺序评估，第一条给出 DROP 的规则即终止评估。另有一组规则只对「来自未关注账号的推荐帖」生效、且只能 DROP（如高召回抓到的垃圾内容）——同一条帖对粉丝可见、对陌生人推荐则被剔除，这是这组规则的典型形态。

**负反馈进入系统的三条路**：

1. 预测头扣分：不感兴趣、静音作者、拉黑作者、举报、划过不停留作为 Phoenix 的预测动作直接进入公式（权重见 1.1），扣的是「当前看帖人被预测会这样做」的概率；
2. 硬过滤：看帖人已拉黑/静音的作者、静音关键词命中的帖，在打分前即被剔除；
3. 账号级标签：他人对某账号的拉黑、举报、垃圾举报经标注管线变成该账号的标签，影响它对其他人（尤其未关注者）的可见性裁决——「被多人举报/拉黑会压制分发」在现行代码中的实际机制在此，且对推荐（未关注）场景更严。

**标注管线（Labeling Path，离线持续运行，不在请求路径上）**：

| 组件 | 职责 |
|---|---|
| grox | 文本与媒体分类器（垃圾、成人、暴力媒体等）＋ 内容数值表示 |
| media-model-proxy / clip | 产出媒体理解结果 |
| agatha | 按他人对账号帖子的拉黑、举报、垃圾举报相对点赞的比例等给账号打标 |
| bdsm | 按账号行为时序识别非真实/滥用行为 |
| user-cred-v2 | 在关注＋互动图上跑 PageRank，得账号信誉分 |
| scarecrow / botmaker | 规则引擎，把模型分与事件转成标签 |
| abuse-enforcement-service | 把标签落为执法；经申诉推翻的执法不重复执行（abuse-ledger-service 把关） |

标签存入存储，供请求路径上的可见性过滤读取。创作者可在 Under the Hood 查看自己账号/帖子上影响可见性的标签聚合统计（2026-09-18 起含法律合规导致的限流信息）。

## 规则

### 2.1 互动垃圾（Engagement Spam）禁项

> 政策原文：「coordinating to exchange engagement in any X features, such as Likes, Polls, Replies, Reposts, Lists, Views, or Follows」——在任何 X 功能中协调交换互动。

- 买卖、转让账号与用户名，或索取账号访问权；
- **协调交换互动**：在点赞、投票、回复、转帖、列表、浏览、关注等任何功能里，协调他人与自己互换互动（互关互评的定性条款即此条，清单中排第二位）；
- 协调或补偿他人进行账号指标灌水；
- 关注刷量（大量关注后取关以抬粉丝数）；短时间无差别大量关注/取关（尤其自动化）；
- 以激进或自动化方式互动来引流；激进地把用户加入列表；
- 复制他人粉丝列表（尤其自动化）；使用或推广第三方服务做上述任何一项；
- 滥用举报功能：批量提交重复/虚假举报；协调、怂恿他人滥用举报去骚扰或试图让对方账号/帖子被限制、删除——**组织化举报本身违规**（与 1.3 的代码注释互证：它既进不了排序，又给自己招违规）。

允许项（划界）：善意手动举报；执法/NGO 经事先同意的自动化举报；真实地协调表达观点不禁，禁的是协调造假。

### 2.2 内容垃圾（Content Spam）禁项

定义要件：以批量、重复、无关或未 solicited 的方式发布、扰乱他人体验。具体包括：批量激进高频的未 solicited 回复/@/私信；发了删、删了重发同一内容；反复发布相同或近乎相同的内容（即俗称 copypasta）或发相同私信；用热门标签操纵对话；单帖或多帖塞过多无关标签；反复发无评论链接且构成账号活动主体；以与原帖无关的内容回复推广；欺骗性编辑放大内容；编辑链接使目的地实质改变。

### 2.3 其他禁项

- 多账号：最多创建/运营 10 个，须各有不同、非重复目的；绕过创建技术限制违规；多号不得雷同互抬。
- 假人设：冒充他人、AI 头像冒充真人等 fake persona；未授权自动化账号、批量注册、封号回归（ban evasion）。
- 合成媒体：欺骗性地将 AI 仿真内容当真发布、且可能在公共议题上造成大范围误导或伤害的禁止；非欺骗性 AI 内容不在此禁。Authenticity 没有一般性 AI 强制标识义务（「Made with AI」发帖披露项为自愿，2026-03 上线）。

- 第三方应用责任：用户对自己授权的第三方应用的行为承担最终责任。
### 2.4 自动化规则（Updated April 2026）

自动点赞禁止；自动回复须对方先自愿订阅（opt-in）；任何 AI 回复机器人上线前须 X 书面批准；2026-02-23 起 API 程序化回复须被原作者 @ 或引用。点赞必须由用户本人发起。

- 机器人账号须明确表明其机器人属性与责任人（Developer Policy）；按关键词搜帖后自动回复未自愿订阅的陌生人，属未 opt-in，禁止。
### 2.5 戏仿/粉丝账号（PCF，2025-04-10 起强制）

四要件：开启 PCF 标签；显示名开头带 parody/fake/fan 类词；bio 带同样的词；头像不得与被仿者相同。不合规先令改资料，再犯可暂停。

### 2.6 执法梯度

后果取决于严重程度与违规史：反垃圾验证 → **限制触达** → 临时锁定 → 暂停；严重者首次即永久暂停。限制触达的官方口径：把帖子排除出搜索结果、趋势与推荐通知；移出 For You 与 Following 时间线；可见范围收窄至作者主页；限制该帖的点赞、回复、转帖、引用、收藏、分享等互动；回复区降序。

### 2.7 判定边界（防定性夸大）

以下形态本身不在禁止之列，不得单独定性违规：互关比例高、回关行为本身（禁的是协调互换与招揽索取这一行为）；单条超短回复（要件是批量、无差别、重复，超短只在构成同文本群发时计入）；单条纯链接帖（原文以「构成账号活动主体」为条件，属账号级形态）；回复串中系统自动带入的多个 @。

**改错字边界**：条文里的「发删重发」与 copypasta 打击的是**操纵性重复**——为霸屏、顶帖、批量灌水而反复发布同一内容。为修正错字删帖重发，是「编辑」的替代动作（免费号无编辑功能、Premium 编辑也有时限），官方**没有**「改超过 N 次算垃圾」的次数线；改 2–3 次、5–6 次，只要目的是修正、最终以修正版为准，不构成垃圾信息。判定要点有二：①看存活状态——旧版本若已删净，平台上只剩一个正本，连「重复」的外观都不存在；数据包会保留已删旧版条目（导出快照），**不得拿包内条数冒充平台存活条数**（与本包验活分级补核口径互文）。②多版本同时存活时，副本只是**整洁问题**（外观像重复帖），归正常、注记「同文副本，可选清理」（删多余、留点赞集中的正本），**不定罪、不入异常**。示例（虚构）：某帖同文 3 条成组——验活后仅 1 条存活 → 只剩正本，合规；3 条全部存活 → 互动最高者为正本判合规、其余 2 条判合规、注记同文副本；0 条存活 → 整组是数据包残影，撤销原判、零处置。成因（是否改错字）须有账号本人陈述才能写入判决，不许猜测。

**口头禅边界**：同文本重复出现 ≠ 无差别群发。回复的定罪须同时过三问——①文本是否含招揽/索取语义（互关、助力、混个脸熟、浇、回访、必回等协调交换话术）：含 → 按 2.1 招揽定罪，与长度无关；②是否对帖应答（每条挂在具体帖子下、是社交应答而非广播）：「是的/好的/加油/晚安/哈哈哈」这类口头禅与招呼语，哪怕同文出现数百次、跨数周自然分布，仍是正常社交用语，不定罪（实况校准：平台所有者本人亦高频发 "yes" 类一词回复）；③只有不含应答性、整段模板原样粘贴多处（长模板群发）才按 2.2 copypasta 从严。注意：口头禅不定罪 ≠ 有流量价值；超短回复对曝光与变现均无贡献，这是质量问题、不是违规问题，两本账分开记。

**蹭流量邀请边界**：主贴公开邀请他人到自己帖下「蹭」曝光（典型如为付费推广帖招人到场），虽无明示对价（没说要赞/评/关），结构上是以流量换到场互动的招揽，命中 2.1 的边——定**中危**，建议删（推广曝光本身不计入变现合格曝光，此类帖对过审只有风险没有贡献）；若明示互换条件、或同类话术反复发，升**违规**。示例（虚构）：一条帖写「我花钱开了推广，流量低的朋友都来我这条下面蹭一蹭」→ 中危。 另一形态——借势型：借灾难、突发事件、逝者等严肃热点标签，挂与话题无关的推广/引流，定**中危**；借普通热门话题标签的，定低危。

**转帖边界**：转帖（RT）是传播与放大行为，转帖人本人没有发出招揽、更没有作出对价承诺，不按「本人协调交换互动」定罪。口径：原文含明示对价招揽（必回类承诺）的转帖，定**中危**（传播违规招揽内容），理由注明「转帖他人招揽内容」；原文只有一般招揽、无对价的转帖，定**低危观察**；若本人在转帖时另附自己的招揽文字（引用帖正文或转帖评论），所附文字按本人招揽另行判定。示例（虚构）：某账号转帖了一条「互关必回，评论区集合」的帖子，自己没有加任何文字 → 中危（转帖他人招揽内容），不按本人的违规论处。

**招揽分层**：招揽不是有/无二值，按「是否组织成一场具体的交换局」分六式、两层定档——**未成局（低危）**：①站牌式：互关类标签、「诚信出摊」等常驻展示，等人自己上门（示例：进度帖文末挂两个互助标签）；②倡导式：劝众人日常去做（「今天你互助了吗」），加强版带即时动员加效果保证仍属未成局，低危顶格；③召唤式：点名喊目标人群现身、留步、到我这里来，含带涨粉目标数的喊话（「新朋友都现身，我要冲五千」）。**成局（中危）**：④招募式：公开征人即刻开团（「还有要一起互助的吗，现在组队」）；⑤组织式：时间＋地点＋动作＋收益四要件齐全（「黄金时段到了，来我评论区互相评论，能涨权重」）；⑥交易式：作者出价或明码标价（见本人出价）。未成局单独定罪概率低，但同类帖成批存在时构成账号画像证据（变现人工审核的负面材料），处置一律建议删、次序在成局之后。

**粉丝帖三级台阶**：一级——纯报数＋守着数字等关口（「看看明早有没有六千粉」），合规；二级——报数＋互关标签/出摊话术，低危；三级——把请求说出口：有对象、有动作、有期限或目标数（「就靠兄弟们了，今晚能不能冲到某个数」），或明示求关/回关承诺，中危。 对照：没有报数/庆祝本体、通篇就是招揽交易的帖（哪怕也谈粉丝话题），不走台阶，按招揽分层与对价规则判（正文写明对价承诺的为违规，校准第 6 题型）。台阶内的对价定位：对价只出现在 hashtag 里、且正文是报数/庆祝的，按第二级低危；正文写明求关或回关承诺的，才进第三级——粉丝帖封顶中危。

**本人出价**：作者以自己的点赞、评论、流量为对价公开招揽（「把你的帖子发到我评论区来，我逐个给你点赞评论」），是交易式招揽，中危。吉祥物口号式的许诺（以账号吉祥物名义说「给你补流量」类）不是本人出价，不按此条；识别要点看许诺的主语是作者本人还是吉祥物、以及有无具体交换动作。

**科普/警示语境豁免**：帖子以劝阻、警示、科普合规为目的而提及违规词汇或行为的（「帖子里互关标签挂太多会导致变现审核失败」），不按所提及的行为定罪——词一样，语境正反两面，罪不成立。**批量审判纪律：禁止「关键词出现即打标」**，定罪只看行为与语境；批量筛查命中的帖子，进入定罪前必须逐条读语境。

**可见性测试帖**：「在时间线上看得到我吗，能看到的吱一声」类，以查可见性为名向所有读者索取回复——答案只能是报到、无信息量，是单向 engagement bait，**低危**，建议删。与真提问帖（求信息、答案有内容）的分界在此。它无交换、无回许、不成局，不到中危。

**邀请码发法对照**：同一邀请码两种命运——主贴里完整推荐＋利益明示（双赢条款当面说清）＋使用说明，是正当推荐，合规；裸丢在无关热门帖的回复区、无语境无说明，属 affiliate spam 观感，**低危**，建议删（低优先）。差别不在码，在发法。

**版本纠错后必须重审**：凡因编辑链/版本合并问题被纠错的帖子，其内容档位必须按现行法条重新审理，不得沿用纠错前的旧结论——纠错只解决了「算几条」，没解决「判几档」。批量审判流程须把「被纠错帖子」自动列入内容重审队列。
