# 审判台空间规格（公开版）

默认产物是一个**空间**（带后端的网页应用），不是文件。理由：全量帖子（动辄上万条）塞进单文件 HTML 会撞上各类预览/打开体积上限；空间把数据放后端、页面按需加载，手机上随便翻，勾选状态存后端、换设备不丢。

空间怎么建，用执行者所在平台的空间/网页应用能力即可；本规格只定**数据模型、页面与行为**，不定实现技术。

## 数据模型

**posts（一条帖一行）**
| 字段 | 说明 |
|---|---|
| id | 帖子 ID（字符串，主键） |
| cls | 展示类别：`主贴` 或 `回复`（原始类型另存 raw_cls 供内部参考，不展示） |
| grp | 分区：`bad`（异常）/ `good`（正常）。**只有这两区**——异常就是异常、没事就是没事，不设「整理项」之类的中间区 |
| grade | 五档：合规/低危/中危/高危/违规（异常必填档位；正常为合规） |
| date | 发帖时间（使用者时区，存 ISO 字符串） |
| text | 正文全文 |
| fav / rt | 点赞 / 转帖数 |
| to_name | 回复对象（回复类才有，如 `@某人`） |
| reason | 判决理由（异常必填：法条＋一句话理由） |
| action | 处置建议 |
| note | 注记（如验活重判说明、口头禅改判说明；**同文副本判合规归正常，在此注记「同文副本，可选清理」**） |
| alive | 验活状态：存活 / 已不存在 / 未果 / 未验 |
| done | 是否已勾选（已删），默认 false；勾选后归入「已删除」页 |
| url | 原帖链接 `https://x.com/<账号名>/status/<id>`（可由 id 现拼，不必存） |

**meta（单行）**：账号名、账号 ID、数据包导出日期、法条基线日期、导入时间、各分区计数（可由 posts 现算，不必存）。

**progress（导入进度，单例）**：`stage`（waiting / parsing / judging / importing / done）、`done`（已完成计数）、`total`（总数，以逻辑帖总数为准，解析对账后确定；对账前先用条目总数）、`updatedAt`，外加 `account`（账号名）与 `pkg`（数据包导出日期）、`btype`（博主类型估计一句话）与 `btypeWhy`（类型判定依据，含关键占比数字；审判完成后回填）——建台时为空，导入后由执行方回填到页头。解析/审判两段由执行方分批回写、导入段由服务端通道灌入时自行回写，首页据此画真实进度条；进度只写真数，禁止估算。

## 导入方式

- **先建空台**：审判开始前（启动流程阶段）就把空间建好——数据为空也要能打开，首页直接是总览仪表盘（无数据时各卡为 0／空态），不设任何导入按钮或启动区：拉包与开工由执行方在后台完成（见「页面与行为」第 3 条）。
- **服务端导入通道（必备，与空间同时建成）**：空间必须自带一个服务端批量导入通道——执行方把判决记录写成 JSON 文件放在自己的工作环境里，空间服务端自己读文件、按 id 幂等灌入、灌一批回写一次进度。**禁止执行方把上万条判决逐条或逐批经对话 / action 参数手搬**：数据量大时不可靠、会损坏记录。通道的具体形态（读哪个目录、什么文件名）由实现决定，但必须在建空台时就一并做好，不许等导入时临场发明。
- 审判工序在执行者本地完成后，把全部判决记录**整包写入一个 JSON 文件**交导入通道，服务端内部分批（每批 ≤1000 条）灌入，写完按验收清单对账；不许执行方拆十几批逐批触发导入。
- **进度回写**：空间须持久存一份导入进度 `{ stage, done, total, updatedAt }`（stage ∈ waiting / parsing / judging / importing / done），解析/审判段由执行方以 `setprogress` 回写；导入段由服务端通道在灌入时自行更新（内部分批、每批更新 done 与 updatedAt 心跳）；首页读取展示，只写真实已完成计数。
- 导入必须幂等：同一批重跑不产生重复行（按 id upsert）。
- 原始数据包**不上传空间**，只有判决结果入库（隐私口径）。
- **通道卡死自检（必备）**：导入通道灌入期间须持续更新 `progress.updatedAt` 当心跳；单批超过 60 秒无更新视为卡死——执行方杀掉导入重跑（幂等，重跑安全），不许干等；交付前必须核对通道回报的入库总行数＝判决文件行数，不一致不许交付、先查通道。

## 页面与行为

单页应用，顶部是**页头**；页头下方一排**顶层主视图切换开关 [审判台 | 法条]**（二选一的大胶囊开关，法条与审判台平级——老台子原样，用户截图为据）；审判台视图内是四张页签：**总览 / 异常 / 正常 / 已删除**（见第 1、7 条）。页签就是导航，不要再另设一排功能按钮。

**页头与滚动规矩（钉死）**：页头整块（标题行、数据源行、切换开关、法条刷新行）是页面最顶部的**普通内容**——不固定、不弹出、不做覆盖层；全页只有**页签行**（审判台四页签／法条四编选项卡）sticky 贴顶，自带不透明实底。任何中间滚动位置——往下读与往回走完全一致——顶部最多只有页签一行；完整页头只在滚回页面最顶端时随内容自然出现，中途不冒出、不弹出。

1. **页头**：标题（X审判台 · @账号名）、数据源一行（数据包导出日期、法条基线）；标题下方放**顶层切换开关 [审判台 | 法条]**：选中侧为黑底胶囊，未选侧为文字；「法条」二字用艺术字（书法感字体）呈现（老台子的标志样子；「审判台」三字用正常字体），点它切到法条视图（见第 7 条）。建台时账号未知：标题先只写「X审判台」、数据源一行写「等待导入」，导入完成后回填。**不要放「导出已删 ID」「重新审判」这类按钮**——实证用户用不上，只添乱；进度与统计由总览和「已删除」页签徽标承担。
2. **页签徽标**：异常页签显示异常总数，正常页签显示正常总数，**已删除页签显示「已删数/异常总数」**（如 `12/480`）——已删除就是已处理，进度看这个徽标即可，别再另挂一行「已处理 x/y」。
3. **总览（仪表盘）**：只放图和进度，不放帖子列表。顶部先是**导入状态区**，按进度 stage 显示三种状态：
   - **等待导入**（还没有数据）：不设启动区、不设按钮——仪表盘照常呈现（各卡 0／空态），顶部最多一行低调状态小字（如「等待后台拉取数据包」）。拉包与开工由执行方在后台自行进行，用户无需在首页做任何操作。
   - **导入中**：进度条＋真实计数——「导入中 · 第 done / total 条」＋百分比（＝ done ÷ total × 100，保留一位小数），阶段名随 stage 变（解析中 / 审判中 / 导入中）。数字只来自后端回写的进度记录，**前端不许自己动画估算**；中途中断就冻在真实位置。stage 未到 done 前，**分诊台五块与博主类型卡不渲染数字**（只显示进度条与状态行）——拿半成品数据算出的统计会误导用户，等灌完再亮。
   - **已完成**：状态区收成一行「导入已完成 · 共 N 条」，下方接回仪表盘。
   数据导入完成后，总览放：
   - **博主类型**（置顶，总览第一张卡）：一张卡片，按帖子内容估计这个账号是什么类型的博主——主类型一句话＋判定依据（带内容分布的关键占比数字，如原创主贴的主题构成、回复占比、招揽类占比）。由执行方在审判完成后据全量内容统计生成、回填进进度记录（`btype` / `btypeWhy`）后展示；只许据统计写，不许凭印象套话。导入前此卡显示「导入后生成」。
   - **清理进度不在总览设卡**：只由「已删除」页签徽标「已删数/异常总数」一处显示，避免与总览重复。
   - **分诊台五块（总览主体，顺序钉死）**：总览是分诊台不是陈列柜——只回答一个问题：先删什么、还剩多少风险。自上而下五块，数字全部由后端按 posts 实时计算，不许写死、不许前端估算：
     1. **北极星「硬伤剩余」**：一个大数字＝违规＋高危的未勾选条数；小字一行带：异常总数与占全量百分比、档位分布（违规/高危/中危各多少，分母＝异常总数）。
     2. **风险存量燃尽**：加权总分＝违规×5＋高危×4＋中危×2（只算未勾选）；勾选删除后实时下降；附一行杠杆文案：最大的 3 个同文簇合计多少条、折合多少分（后端实算，不许拿约数充数）。
     3. **再犯周趋势**：按周分桶的异常率（该周异常数÷该周总数），柱状呈现；最近一周单独标注异常数与其中违规数。数据包日期跨度有限，**只能按周、不许按月造趋势**。
     4. **先删队列 Top 5**：按 档位权重（违规 100/高危 50/中危 10）×（1＋点赞＋转帖） 降序取前 5；点一行跳到异常页并按 ID 定位高亮该帖；榜下小字注明「互动量为点赞+转帖，非浏览量」。
     5. **病因条**：一行三数——占比最大的违规类别占异常的百分比、同文簇覆盖异常回复的百分比、最大同文簇的条数。
   - **数据边界（不许装）**：数据包没有浏览量字段，任何「曝光加权」只能用点赞+转帖作互动代理并明确标注；燃尽的「燃速」要等有两次勾删记录后才能算，之前不许预估。
   - **百分比铁律**：百分比＝计数 ÷ 分母 × 100，保留一位小数；图旁必须标注分母口径；数字与图形（柱高/条宽）必须一致。⚠️ 实测踩过的坑：把 0–1 的小数直接当 % 显示（4.8% 显示成 0%），交付前逐个手算核对一遍。
4. **异常页**：顶部一个**下拉选择器（主贴 / 回复）**，选哪类下方就只显示哪类卡片；只显示未勾选（待处理）的，勾掉一张少一张。卡片：勾选框、档位徽标、日期 · 类别、♥/转、正文全文、理由框（法条＋理由）、处置建议、「打开原帖 ↗」链接（新开页）。勾选即写后端（done=true），该卡从异常页消失、出现在已删除页。组内按严重程度排序（违规 → 高危 → 中危 → 低危，同档时间倒序）。顶部带搜索框（关键词 / 帖子 ID）。
5. **正常页**：顶部同样的**下拉选择器（主贴 / 回复）**；紧凑行分段加载（每批 ≤100 行，不许一次渲染全部——上万行会卡死页面，这是硬规矩）：日期 · 类别 · ♥ · 正文（可截断）· 注记（灰色小字，同文副本的注记在这里露出）· 打开链接。行带勾选框（主要给同文副本这类可选清理用），勾后同样归入已删除页。顶部带搜索框。
6. **已删除页**：顶部**下拉选择器（主贴 / 回复）**；显示全部已勾选的帖（卡片或紧凑行均可，需带档位与理由方便复核）；**取消勾选可放回**原区（异常或正常）。
7. **法条（必备，不许省）**：法条是与审判台平级的顶层视图，从标题下方的 [审判台 | 法条] 切换开关进入（不占四页签、不是页头小按钮），全屏只读展示法条全文——用执行方手头当期法条全文，构建时嵌入静态渲染即可，不需要后端。**排版**：艺术字（书法感字体）**只许用在切换开关的「法条」两个字上**；「审判台」三字、法条内的编名/节名标题、正文条文一律正常字体（标题加粗即可），正文左对齐、正常字距行距，不许两端对齐拉伸——老台子原样，看得清最重要。**法条视图的结构钉死**：顶部保留台子标题与 [审判台 | 法条] 切换开关（即它的标题栏，点「审判台」切回，不另设关闭按钮）；开关下方一排**选项卡，选项卡就是法条的四编——只写四个名字：算法 / 规则 / 变现 / 黑箱清单（不带「第X编」）**，做成四颗等宽的胶囊按钮，选中黑底白字、未选浅底黑字；点哪个，下方就只显示那一编的全文，切换不整页刷新。不许做成目录列表逐层展开，也不许把全文摊成一堵没有选项卡的长墙。用户看得见判决，就必须随时查得到法律；缺了它不算交付。
   - **法条刷新按钮**：法条视图顶部放一颗低调的「刷新法条」按钮＋一行状态小字（上次核对时间＋结论：已是最新／已更新／核对中）。点击只登记刷新请求（后端单例 lawrefresh｛requestedAt, status, lastCheckedAt, note｝；action：requestlawrefresh／getlawstate），由执行方 AI 在后台回四个源头核对（算法仓库、Authenticity、Original Content Rewards、Creator Monetization Standards）——有变化更新法条内容并回写「已更新」，无变化回写「已是最新」与核对时间。审判台视图不放此按钮。

## 视觉基调（商务书，单一皮肤）

整页只有一套皮肤，不许做皮肤切换：象牙纸白底、墨黑正文、标题用衬线体（Noto Serif CJK 一类）、章节间细分割线、深藏蓝为主色＋一线商务红点缀、卡片留白放宽、无辉光、无渐变发光。字阶固定六档：页头 20 / 卡片标题 16 / 小标题 14 / 正文 14 / 次级 13 / 元信息 12。卡片全站一样式（圆角 16、内边距 20、同一套边线），卡间距统一 16。按钮成排时等宽等高、边线齐平；页签用两行式（上行标签、下行小字计数），四格同构，徽标数字不许撑破格子。**等宽字体只许套纯数字与日期片段，中文一律走正文字体**（整段中文套等宽会扭曲变形，实测踩过）；正文左对齐、正常字距，不许两端对齐、不许负字距。档位徽标可用深浅区分严重程度，但全站同一套色板，审判台与法条像同一个产品。法条正文保持易读文档排版。手机宽度优先。

## 验收清单（交付前必做）

1. **对账**：空间内总行数 = 数据包逻辑帖总数（编辑旧版本即鬼影不单独计数、不单独审，只审主贴）；异常主贴＋异常回复＋正常主贴＋正常回复 = 总数；随机抽 5 条与本地判决记录逐字段核对。
2. **仪表盘手算核对**：总览数字（硬伤剩余、燃尽分、周趋势各周异常率、先删队列排序、病因条三数）逐个用计数手算一遍，与页面显示一致才算过——这一项专防小数当百分比的坑。
3. **切换与滚动**：[审判台｜法条] 与法条四选项卡连点切换，页面不跳动、两视图不重叠闪烁，同一时刻只渲染一个视图；滚动验收——页头是顶部普通内容、全页只有页签行 sticky 贴顶，中段回滑时顶部只有页签一行，滚回最顶端页头随内容自然出现，无弹出层、无覆盖层；做不到不算交付。
4. **法条在位**：标题下方有 [审判台 | 法条] 顶层切换开关；切到法条视图，顶部保留标题与开关、开关下方四编作选项卡切换；内容与当期法条全文一致（抽查标题与权重表数字）。
5. **导入进度三态与真实性**：等待导入 / 导入中 / 已完成三态显示正确；进度数与 `setprogress` 回写记录抽查一致（任取一批核对）；进度条宽度与百分比数字一致。
6. **真机位验收**：以手机宽度打开空间，四张页签逐页看一遍：不空白、不重叠、理由与按钮齐全，下拉切换主贴/回复生效。没亲眼看过不许说做好了。
7. **勾选实测**：在异常页勾一条 → 它从异常页消失、出现在已删除页、已删除徽标数字 +1 → 在已删除页取消勾选 → 它回到异常页。
8. **链接抽查**：随机 3 条点「打开原帖」，直达对应帖子。
9. 全过才交付，交付报告附对账数字与空间链接。

## 空间内容红线（用户是来用的，不是来了解功能的）：空间页面里**不许放复审日志、对账过程、验活底账、文件路径、导入记录这类给执行者看的技术长文**——包括但不限于把开工报告、复审说明、对账数字段落写进首页或任何页面。首页（总览）只放用户要用的东西：标题、数据源一行、仪表盘、进度。审判过程与对账记录只写进你在对话里给用户的**交付报告**，永远不进空间。

## 人性化硬规矩（体验，不许打折）

1. **吸顶只有页签行**：页头不固定、不弹出（见「页头与滚动规矩」）；唯一 sticky 的页签行高度克制、自带不透明实底，正文区留与之匹配的间距；页内跳转/展开定位给目标元素留 `scroll-margin-top`。交付前实测：滑到中段，页签行下第一行完整可见。
2. **滑动流畅**：长列表分段加载（首屏 ≤500 条、其余滚动触发或按钮加载），滑动不整页重排、不跳回顶部，加载新段保持滚动位置。
3. **触控友好**：勾选框、按钮、链接、页签的可点区域 ≥44px；勾选后状态变化与计数立即反馈。
4. **回到顶部**：右下角常驻按钮，滚动超过一屏后出现。
5. **搜索常驻**：异常、正常两页的搜索框固定在该页顶部，随处可搜。
